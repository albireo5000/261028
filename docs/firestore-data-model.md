# Firestore 데이터 구조와 읽기 횟수 예상

Firebase 무료 요금제(Spark)는 **하루 읽기 5만 회, 쓰기 2만 회**까지입니다.
이 문서는 컬렉션 구조와, 화면 하나를 열 때 문서를 몇 개 읽는지 정리한 것입니다.

## 1. 컬렉션 구조

| 경로 | 문서 ID | 주요 필드 | 누가 읽나 | 누가 쓰나 |
|---|---|---|---|---|
| `members/{email}` | 이메일 주소 | `role`('member' 또는 'admin'), `displayName` | 본인, 교수 | 교수 |
| `research/{id}` | 자동 | `title`, `summary`, `authors[]`, `year`, `tags[]`, `links[]`, `createdAt` | 누구나 | 교수 |
| `teaching/{id}` | 자동 | `course`, `semester`, `title`, `description`, `url` | 누구나 | 교수 |
| `posts/{postId}` | 자동 | `title`, `body`, `researchId?`, `authorUid`, `authorName`, `createdAt`, `commentCount` | 승인 회원 | 승인 회원 |
| `posts/{postId}/comments/{commentId}` | 자동 | `postId`, `body`, `authorUid`, `authorName`, `createdAt` | 승인 회원 | 승인 회원 |

- 타입 정의는 `src/services/types.ts`와 같습니다.
- `members` 문서 ID는 Google 이메일을 **소문자 그대로** 씁니다. 보안 규칙이 로그인한 이메일과 글자 하나까지 비교합니다.
- `createdAt`은 `2026-09-15T09:00:00.000Z` 형식의 **문자열**로 통일합니다. 형식이 섞이면 최신순 정렬이 어긋납니다.
- 자료 파일은 올리지 않고 `url`(Google Drive 공유 링크 등)만 저장합니다.
- **승인되지 않은 사람**은 `members`에 문서가 없습니다. 로그인은 되지만 역할이 `pending`이 됩니다.
- 글을 지울 때 댓글은 자동으로 지워지지 않습니다(Cloud Functions 미사용). 화면에서 댓글을 먼저 지우고 글을 지웁니다.

### 필요한 색인(index)
- `research`: `tags`(array-contains) + `createdAt`(내림차순) — 태그 필터용. 처음 실행하면 콘솔 오류 메시지에 색인 만들기 링크가 뜨니 눌러서 만듭니다.

## 2. 화면별 읽기 횟수 예상

목록은 한 번에 **20개**까지만 읽습니다(`PAGE_SIZE`). 실시간 구독은 **열린 토론 글의 댓글**에만 씁니다.

| 화면 | 읽는 문서 | 1회 방문 시 읽기 |
|---|---|---|
| 로그인 직후 | `members/{내 이메일}` 1개 | 1 |
| 홈 (비회원) | 최근 연구 3 | 3 |
| 홈 (회원) | 최근 연구 3 + 최근 토론 3 | 6 |
| 연구 목록 | 연구 최대 20 | ≤ 20 |
| 연구 상세 | 연구 1 | 1 |
| 수업 자료 | 자료 최대 20 | ≤ 20 |
| 토론 목록 | 글 최대 20 (댓글 수는 `commentCount`로 표시해 따로 안 셈) | ≤ 20 |
| 글쓰기 화면 | 관련 연구 선택용 연구 최대 20 | ≤ 20 |
| 토론 글 상세 | 글 1 + 관련 연구 1 + 댓글 N개 | 2 + N |
| 상세 화면에 머무는 동안 | 새 댓글이 달릴 때마다 그 댓글 1 | +1/건 |

※ 보안 규칙 안의 `exists()`/`get()`(승인 여부 확인)도 읽기로 계산됩니다. 요청 1번에 보통 1~2회가 더해집니다.

## 3. 하루 사용량 어림셈

가정: 하루 방문 200회(비회원 150, 회원 50), 회원 1명이 하루 글 상세 10개(댓글 평균 10개) 열람.

- 비회원: 150 × (홈 3 + 연구 목록 20 + 상세 1) ≈ 3,600
- 회원 50명: 50 × (홈 6 + 토론 목록 20 + 상세 10 × 12 + 규칙 확인 약 30) ≈ 8,800
- **합계 약 1만 2천 회 / 하루** → 한도 5만 회의 약 25%

쓰기는 글·댓글 작성(댓글 1건 = 댓글 1 + `commentCount` 1 = 쓰기 2회)뿐이라 한도 2만 회에 한참 못 미칩니다.

## 4. 한도를 지키는 규칙 (코드 수정 시 확인)

1. 목록 조회에는 항상 `limit(20)`을 붙이고, "더 보기"는 `startAfter`로 다음 20개를 읽는다.
2. `onSnapshot`(실시간 구독)은 `watchComments` 하나만 쓴다. 화면을 떠나면 해제한다.
3. 댓글 수를 세려고 댓글 컬렉션을 읽지 않는다. `commentCount`를 쓴다.
4. 연구 태그 목록은 `src/config/site.ts`에 둔다.
5. Firebase 콘솔 > 사용량(Usage) 탭을 처음 몇 주는 매주 확인한다.
